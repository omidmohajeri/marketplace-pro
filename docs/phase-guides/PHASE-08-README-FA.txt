فاز هشتم بازارگاه چندفروشندگی - حمل‌ونقل و رهگیری مرسوله
=========================================================

امکانات این بسته
----------------
1) تعریف روش‌های ارسال با هزینه پایه و هزینه هر کیلوگرم
2) امکان تعیین آستانه ارسال رایگان
3) برآورد بازه زمانی تحویل
4) محاسبه نرخ روش‌های فعال در ShippingQuoteService
5) ایجاد مرسوله برای سفارش اختصاصی هر فروشنده
6) ثبت شرکت حمل‌کننده و کد رهگیری
7) نمایش عمومی تاریخچه رهگیری با کد رهگیری
8) ثبت رویدادهای جابه‌جایی توسط مدیر
9) نگهداری snapshot نشانی مقصد برای مرسوله

پیش‌نیازها و فرض‌ها
-------------------
- پروژه Laravel 12 و PHP 8.3+ از فازهای قبلی آماده باشد.
- مدل‌های Seller، SellerOrder، User و middleware role وجود داشته باشند.
- جدول seller_orders دارای seller_id، status و currency باشد.
- هر SellerOrder در این پیاده‌سازی حداکثر یک Shipment اصلی دارد.
- نام layout عمومی `layouts.app` است؛ اگر در پروژه نام دیگری دارد، Bladeها را هماهنگ کنید.
- مبالغ به کوچک‌ترین واحد پولی ذخیره می‌شوند و باید در کل پروژه یکسان باشند.

نصب
----
1) پوشه‌های app، database، resources و routes را با پروژه ادغام کنید.
2) محتوای routes/phase8.php را به routes/web.php اضافه کنید.
3) اجرا:
   php artisan migrate
   php artisan optimize:clear
4) مسیرهای نمونه:
   /seller/shipments
   /shipping/track/{trackingNumber}

محاسبه هزینه ارسال
------------------
نمونه استفاده در سمت سرور:

$quotes = app(\App\Services\ShippingQuoteService::class)
    ->quotes($weightKg, $subtotal, 'IRR');

وزن و مبلغ سفارش باید از اقلام سفارش و داده‌های معتبر دیتابیس محاسبه شوند.
هرگز وزن، subtotal یا هزینه نهایی را بدون محاسبه و اعتبارسنجی سمت سرور از مرورگر قبول نکنید.

نکته مهم درباره اتصال به Checkout
---------------------------------
فازهای قبلی هنوز checkout نهایی و یکپارچه‌ای تحویل نداده‌اند. این فاز محاسبه نرخ را به شکل سرویس فراهم می‌کند؛
انتخاب روش ارسال و ذخیره هزینه آن باید هنگام تکمیل checkout انجام شود.
در زمان ایجاد SellerOrder/سفارش نهایی، برای هر فروشنده باید روش ارسال و سهم هزینه ارسال مشخص شود.
اگر یک سفارش اصلی به چند SellerOrder تقسیم می‌شود، هزینه ارسال باید برای هر مرسوله جداگانه محاسبه شود.

ثبت مرسوله
----------
پس از پرداخت موفق و آماده‌سازی سفارش، برای هر SellerOrder یک مرسوله ایجاد کنید.
نمونه سرویس:
app(\App\Services\ShipmentService::class)->create($sellerOrder, $data, $sellerId);

کنترل مالکیت در سرویس انجام می‌شود. shipping_address_snapshot باید از آدرس سفارش ذخیره‌شده روی سرور ساخته شود.
در این نسخه endpoint ثبت مرسوله به‌صورت پایه وجود دارد، اما فرم انتخاب سفارش/آدرس در پنل فروشنده کامل نشده است.

رهگیری
------
فروشنده پس از تحویل بسته به شرکت حمل، کد رهگیری را ثبت می‌کند.
مدیر می‌تواند رویدادهای in_transit، delivered، failed و returned را ثبت کند.
صفحه عمومی رهگیری فقط وضعیت و رویدادها را نشان می‌دهد و آدرس مقصد را افشا نمی‌کند.

محدودیت‌های این نسخه
--------------------
- اتصال API واقعی به شرکت پست، تیپاکس، چاپار یا شرکت‌های دیگر وجود ندارد.
- به‌روزرسانی خودکار وضعیت‌ها وجود ندارد؛ رویدادها در نسخه فعلی دستی ثبت می‌شوند.
- پنل CRUD کامل برای روش‌های ارسال در این فاز نیست؛ روش‌ها باید فعلاً از دیتابیس یا seeder مدیریت شوند.
- محاسبه مناطق جغرافیایی، وزن حجمی، ابعاد بسته، بیمه، مالیات و بسته‌بندی هنوز پیاده‌سازی نشده است.
- یک مرسوله برای هر SellerOrder فرض شده؛ ارسال چندبسته‌ای در این نسخه پشتیبانی نمی‌شود.
- قواعد دقیق تخصیص هزینه ارسال بین چند فروشنده باید در checkout نهایی تعیین شود.
- این بسته روی اسکیمای واقعی پروژه اجرا و تست یکپارچه نشده است؛ پیش از production migrationها، روابط و مسیرها را با کد موجود تطبیق دهید.

نمونه Seeder برای روش ارسال
---------------------------
ShippingMethod::create([
    'name' => 'پست پیشتاز',
    'code' => 'post_pishtaz',
    'base_cost' => 800000,
    'cost_per_kg' => 150000,
    'free_shipping_threshold' => 50000000,
    'estimated_min_days' => 2,
    'estimated_max_days' => 5,
    'is_active' => true,
]);

اعداد بالا فقط نمونه هستند؛ نرخ واقعی را با تعرفه معتبر کسب‌وکار خود جایگزین کنید.
