MARKETPLACE PRO — بسته جامع ادغام فازهای 01 تا 20
===================================================

این بسته، سورس فازهای 1 تا 20 را در یک ساختار واحد Laravel جمع کرده و چند ناسازگاری شناخته‌شده را اصلاح می‌کند.
این خروجی هنوز «نسخه تأییدشده برای production» نیست؛ موارد نیازمند تکمیل در بخش محدودیت‌ها آمده است.

پیش‌نیازها
----------
- PHP 8.3 یا بالاتر
- Composer 2
- MySQL 8 یا MariaDB سازگار
- Node.js 20+ و npm
- Laravel 12 (در composer.json پروژه تعریف شده)
- افزونه‌های PHP موردنیاز Laravel و درایور PDO متناسب با دیتابیس

نصب اولیه
---------
1) محتویات ZIP را در پوشه پروژه استخراج کنید.
2) فایل .env.example را به .env کپی و اطلاعات دیتابیس را تنظیم کنید.
3) در ریشه پروژه اجرا کنید:
   composer install
   cp .env.example .env
   php artisan key:generate
   php artisan migrate
   npm install
   npm run build
   php artisan serve

برای اجرای تست‌ها پس از نصب وابستگی‌ها:
   php artisan test

نکته: پوشه vendor داخل ZIP نیست و باید با composer install ساخته شود.

ادغام مسیرها
-------------
- routes/web.php مسیرهای اصلی را دارد و routes/marketplace-modules.php را بارگذاری می‌کند.
- routes/marketplace-modules.php فایل‌های مسیر فازهای 2 تا 17 را به ترتیب بارگذاری می‌کند (از جمله مسیرهای پرداخت فاز 6).
- مسیرهای API فاز 19 از routes/api.php بارگذاری می‌شوند.
- مسیرهای قدیمی سفارش فروشنده در فاز 4 حذف شده‌اند تا مسیرهای جدید SellerOrder فاز 5 تکراری نشوند.
- مسیر orders.show برای مالک سفارش اضافه شده تا بازگشت پرداخت مقصد داشته باشد.

- جدول coupons فاز 1 حفظ شده و migration توسعه‌ای جایگزین ایجاد دوباره جدول شده است.
- مقدار درصدی قدیمی فاز 1 با مقدار percent سازگار شده است.
- افزایش شمارنده مصرف کوپن فقط هنگام ایجاد سابقه جدید انجام می‌شود.
- migration کیف پول بعد از payout_requests قرار گرفته تا foreign key به جدول موجود اشاره کند.
- وضعیت محصولات در جست‌وجو و API با active (اسکیمای پایه) سازگار شده است.
- مرتب‌سازی پرفروش‌ها از رابطه اقلام سفارش محاسبه می‌شود.
- رابطه supportTickets به User افزوده شده است.
- layout پنل‌های افزوده‌شده با admin.layout فاز 3 هماهنگ شده است.
- alias میان‌افزار role برای مسیرهای مدیر و فروشنده در bootstrap/app.php ثبت شده است.
- وابستگی Laravel Sanctum برای مسیر محافظت‌شده API در composer.json افزوده شده است.
- پیکربندی‌های پایه برنامه برای دیتابیس، نشست، کش، صف، فایل، لاگ، ایمیل، احراز هویت و view اضافه شده‌اند.
- جداول پایه نشست، بازیابی رمز و صف دیتابیسی به migrationها افزوده شده‌اند.
- فایل پیکربندی PHPUnit و کلاس پایه تست ایجاد شده‌اند.
- خطاهای نحوی PHP در فایل‌های bootstrap، public و migration کش اصلاح شده‌اند؛ بررسی php -l روی همه فایل‌های PHP بدون خطا انجام شد.
- مدیر از فرم عمومی نمی‌تواند سفارش را به paid تغییر دهد؛ فقط تأیید پرداخت سرور این وضعیت را ثبت می‌کند.
- پاسخ پرسش محصول به مدیر یا فروشنده مالک محصول محدود شده است.
- PaymentService پس از تأیید واقعی پرداخت، SellerOrderها را paid می‌کند و اعتبار خالص آن‌ها را با idempotency به کیف پول فروشنده ثبت می‌کند.
- صفحات پایه نمایش محتوای سایت، تیکت پشتیبانی و جزئیات سفارش افزوده شده‌اند.

اجرای کنترل‌شده
---------------
ابتدا روی دیتابیس آزمایشی:
  php artisan migrate:fresh --seed
  php artisan route:list
  php artisan test
  npm run build

هشدار: migrate:fresh تمام داده‌ها را حذف می‌کند؛ فقط روی دیتابیس توسعه اجرا شود.
برای دیتابیس موجود فقط php artisan migrate اجرا کنید و قبل از آن backup بگیرید.

محدودیت‌ها و کارهای الزامی پیش از بهره‌برداری
---------------------------------------------
1) Checkout کامل و یکپارچه هنوز در این بسته پیاده‌سازی نشده است؛ جریان ساخت Order باید به Cart، CouponService، هزینه ارسال، SellerOrderSplitter و PaymentService متصل شود.
2) روش محاسبه تخفیف، مالیات، هزینه ارسال و تخصیص تخفیف/ارسال بین چند فروشنده باید در Checkout نهایی و به‌صورت server-side تعیین شود.
3) Adapter پرداخت نمونه عمداً درگاه واقعی نیست؛ باید با مستندات رسمی درگاه منتخب و کلیدهای واقعی پیاده‌سازی و verify شود.
4) Laravel Sanctum در وابستگی‌های Composer افزوده شده و API نسخه 1 از auth:sanctum استفاده می‌کند؛ صدور توکن و جریان ورود/ثبت‌نام API، CORS و rate limit اختصاصی هنوز تکمیل نشده است.
5) اتصال API شرکت‌های حمل‌ونقل و استعلام/چاپ برچسب ارسال انجام نشده؛ رهگیری فعلاً دستی است.
6) پنل کامل CRUD برای تمام تنظیمات محتوا، روش‌های ارسال، رویدادهای امنیتی و همه وضعیت‌های مرجوعی هنوز تکمیل نشده است.
7) اعلان‌ها در زیرساخت آماده‌اند، اما همه رویدادهای سفارش/پرداخت/ارسال به آن‌ها متصل نشده‌اند.
8) سیاست مرجوعی، آزادسازی کوپن، برگشت اعتبار کیف پول و ثبت refund_debit باید مطابق سیاست مالی فروشگاه تکمیل شود.
9) مهاجرت پولی پروژه بر مبنای واحد صحیح ارز (integer smallest unit) است؛ واحد پول و گرد کردن را در کل سیستم یکسان نگه دارید.
10) این سورس روی محیط واقعی اجرا نشده و تست سرتاسری/امنیتی/بار انجام نشده است. قبل از انتشار عمومی بازبینی توسعه‌دهنده لازم است.
